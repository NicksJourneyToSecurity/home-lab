# Session 01: Building the lab foundation

**Date:** 2026-11-09  |  **Phase:** 1 – Foundation  |  **Time spent:** One day, roughly 09:15–14:20 including breaks

## Goal

Build the base of my home lab: install virtualisation software, create an isolated lab network, and set up a first Linux server that is updated, firewalled and saved as a restore point. Everything in later phases (monitoring, Windows, attack and detect) builds on this.

## Setup

|Item|Detail|
|-|-|
|Host|Windows 11 desktop: Ryzen 5 5600, 16GB RAM, VMs stored on a separate HDD|
|Virtualisation|Oracle VirtualBox 7.2|
|Lab network|VirtualBox NAT Network `LabNet`, `10.10.10.0/24`, DHCP on|
|Guest|Ubuntu Server 26.04.1 LTS (`lab-ubuntu-01`), IP `10.10.10.3` assigned by DHCP|
|VM resources|2 vCPU, 2GB RAM, 25GB dynamically sized disk|

The NAT Network lets lab VMs reach the internet for updates and talk to each other, while devices on my home network can't reach them. Before any attack work in later phases, the lab will move to a fully isolated Internal Network.

## Steps

1. **Checked hardware virtualisation** was enabled on the host CPU.
2. **Installed VirtualBox 7.2** and set the default VM folder to the HDD to save space on the 256GB SSD.
3. **Created the lab network.** Switched VirtualBox to Expert mode, then created a NAT Network named `LabNet` on `10.10.10.0/24` with DHCP enabled.
4. **Downloaded and verified the Ubuntu Server ISO.** Generated the file's SHA256 hash and compared it with the official value Ubuntu publishes, to confirm the download hadn't been corrupted or tampered with.

```powershell
   certutil -hashfile ubuntu-26.04.1-live-server-amd64.iso SHA256
   ```

   Result: `cc8a95cde20f6ced61a322420de00f10cc3c90ced545daa46cb9c1a117f1d927`, which matched the official SHA256SUMS entry.

5. **Created the VM** `lab-ubuntu-01`, attached the ISO, skipped unattended installation so I could do the install manually, and set Adapter 1 to NAT Network `LabNet` (promiscuous mode left on Deny).

   !\[VM network adapter on LabNet](screenshots/03-vm-network.png)

6. **Installed Ubuntu Server** through the text installer: standard server install, default storage on the virtual disk, OpenSSH server installed, no extra snaps, and Ubuntu Pro skipped.
7. **Applied all updates and rebooted.** After rebooting, the login message confirmed 0 updates were waiting.

```bash
   sudo apt update \&\& sudo apt full-upgrade -y
   sudo reboot
   ```

8. **Set the timezone** so logs carry the correct time, which matters for the monitoring work in phase 2. This took a few attempts (see Problems \& fixes).

```bash
   sudo timedatectl set-timezone Europe/London
   ```

9. **Checked the VM's network address.** The interface `enp0s3` had been given `10.10.10.3` by LabNet's DHCP, confirming the VM was on the lab network.

```bash
   ip a
   ```

10. **Enabled the firewall**, allowing only SSH in. The status confirmed the firewall was active, with incoming traffic denied by default, outgoing allowed, and port 22/tcp (OpenSSH) allowed for IPv4 and IPv6.

&#x20;   ```bash
    sudo ufw allow OpenSSH
    sudo ufw enable
    sudo ufw status verbose
    ```

    !\[Timezone, IP address and firewall status](screenshots/04-timezone-ip-ufw.png)

11. **Checked listening services** to see what was accepting connections.

&#x20;   ```bash
    sudo ss -tulpn
    ```

|Service|Listening on|What it is|Reachable from the network?|
|-|-|-|-|
|SSH|Port 22 (all addresses)|Remote login, started on demand by systemd|Yes, the only service that is|
|systemd-resolved|127.0.0.53 / 127.0.0.54, port 53|Local DNS lookups|No, localhost only|
|chronyd|127.0.0.1, port 323|Time synchronisation|No, localhost only|
|systemd-networkd|10.10.10.3, UDP port 68|DHCP client receiving the VM's IP address|No, client only|

    SSH was the only service open to other machines, which matches the firewall rules.

12. **Confirmed automatic security updates** were enabled and running.

&#x20;   ```bash
    systemctl status unattended-upgrades
    ```

    !\[Listening services and unattended upgrades](screenshots/05-services-updates.png)

13. **Shut down and took a snapshot** named `01-clean-hardened` as a restore point.

## Problems \& fixes

|Problem|Cause|Fix|
|-|-|-|
|Network Manager wasn't in the VirtualBox Tools menu|VirtualBox 7.2 defaults to Basic mode, which hides advanced features|Switched the experience level to Expert in Preferences; the Network tool then appeared in the sidebar|
|No ISO available to attach when creating the VM|The Ubuntu ISO hadn't been downloaded yet, and VirtualBox only lists ISOs it already knows about|Downloaded the ISO, then used Other in the ISO box to browse to it|
|Couldn't find the "dynamically allocated" disk option|VirtualBox 7.2 no longer uses that wording|Leaving Pre-allocate Full Size unticked gives the same result|
|The checksum command wasn't working at first|Command needed the exact ISO file name, run from the folder holding the file|Ran it from Downloads with the full file name; the hash then generated correctly and matched|
|Timezone command failed several times|Typos in the command (`timedeatect1`, `timedatect1`, `timedatextl` instead of `timedatectl`, where the last letter is a lowercase L, not a 1), then `europe/london` rejected as an invalid timezone because Linux is case-sensitive|Typed the command exactly and used the correct capitals: `Europe/London`|
|Typing went into the log output instead of the command line|`systemctl status` opens a scrolling viewer (pager) that captures keypresses|Pressed `q` to exit the viewer and return to the prompt|
|"Log file already in use" when trying to take the snapshot|The VM was still running, so VirtualBox still had its log file open|Exited the viewer with `q`, ran `sudo shutdown now`, waited for Powered Off, then took the snapshot|

## What I learned

* VirtualBox 7.2 hides some features in Basic mode, so if a guide mentions a menu I can't find, the experience level is the first thing to check.
* Verifying a download's SHA256 hash against the official value is a quick way to confirm a file is genuine before installing it.
* Linux is case-sensitive and exact: `timedatectl` ends in a lowercase L, and `europe/london` isn't the same as `Europe/London`. Reading the error message tells you which part is wrong.
* A service listening on `127.0.0.x` is only reachable from inside the machine itself, so when checking what's exposed, the address matters as much as the port.
* Commands like `systemctl status` open a viewer rather than returning to the prompt, and `q` gets out of it.
* What a snapshot is and how crucial snapshots are: a saved copy of the VM's exact state that I can restore in seconds, so I can experiment and break things without having to rebuild. A VM has to be fully powered off before taking one.
